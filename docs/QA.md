# 验证记录

## 2026-10-13 飞行模式

自动化：58 项 Vitest 测试、TypeScript 检查、Vite 生产构建通过。覆盖三种机体起飞/悬停、俯仰方向飞行、合成速度限制、30/60/120 Hz 耗能与移动、启动门槛、补能延迟、限速下坠、楼顶落脚/再起飞、立体墙体/机体碰撞、空中近战、敌机追击/返航、武器朝向及镜头响应。

独立审查发现并复现了扎古越屋顶边缘反复起降的问题，修正为按完整机体平面范围保持屋顶净空。普通/夏亚扎古均有回归测试；复审未发现剩余重要问题。

Chrome 实测通过 browser-harness/CDP 发送真实键鼠事件，游戏状态只通过只读 sdDiagnostics 观察。暂停通过浏览器原生 document.exitPointerLock() 触发，与游戏正常鼠标解锁处理相同。未修改玩家耐久、能量或敌机状态。

- F 起飞，Space 上升，抬头 W：高度从 13.70 增至 22.62，前向坐标从 55 变为 44.40；松键后速度归零，后续 0.5 秒坐标保持不变。
- 悬停射击生效，武器热量升至 46；F 降落至 y=0 后恢复充能，浏览器采集的脚本异常为空。
- 飞行至城市建筑上方 `(41.61,42.40,55)`，Ctrl 下降准确落在高度 32 的屋顶，状态为 grounded、相对高度为 0；再次 F 可从屋顶起飞。
- Shift + Space 到达高度上限 100；能量耗尽后转为 descent，下落速度限制为 -12，未在空中充能。
- 空战画面可见多台扎古起飞追击。1920×889、中画质取样为 60 FPS（起飞首次取样 42 FPS），不代表所有设备性能。

截图：本地 artifacts/flight-roof.png、artifacts/flight-low-energy.png。最终操作手感由用户亲自试玩验收。

验证日期：2026-10-11。Windows、Node.js 24.15.0。测试使用真实本地 Kenney 素材与项目分件模型。

完整三波自动操控实战用时约 42.17 秒，结束时高达剩余耐久 164。该值为验证用输入脚本结果，不是普通玩家预期通关时长。测试只读取诊断状态，操作通过真实输入完成，没有修改耐久、伤害、波次或敌机状态。

连续三次重开的 GPU 统计均为 168 个几何、18 个纹理，未出现增长。军刀首次显示会上传其几何，切换/重开后由所属机体正常释放。

## 性能记录

Edge 155、ANGLE AMD Radeon(TM) Graphics、960×640、中画质：实际作战主要约 59–60 FPS，三波战斗取样约 52–60 FPS。Chrome 1280×720 中画质验证出击和重开；首次初始化取样约 47 FPS，资源就绪后准备画面约 60 FPS。

早期使用禁用 GPU 的搜索测试浏览器，软件渲染明显较慢；最终交互测试改用独立、保留沙箱及硬件加速的浏览器。性能数值仅代表上述分辨率与环境，不保证所有设备相同表现。

## 再次验证

1. 执行 `npm.cmd test`、`npm.cmd run typecheck`、`npm.cmd run build`。
2. 双击 start-game.cmd，在 Chrome/Edge 打开。确认四款机体及武器展示、城市纹理和声音。
3. 进入战斗，检查 WASD、鼠标、1/2、Shift、Space、右键和 Esc。
4. 靠近建筑后转动视角，检查肩后镜头、枪口遮挡和 AI 绕路。
5. 切到其他窗口确认暂停，继续/重开后确认输入不残留。
6. 完成胜负流程，反复重开；以 `?debug=1`、`sdDiagnostics()` 检查状态和渲染资源统计。
